# Chess Vision installed-APK runtime QA

This is a separate, disposable Android instrumentation app. It runs against the installed Chess Vision APK and does not replace its assets, rules, or storage implementation. It must be signed with the same debug key as the target. The Gradle file references the existing project-local key; the key itself is not included.

The runner drives the target WebView with Android touch events. JavaScript inspections select known correct/incorrect exercise targets and verify results; they do not call answer handlers or insert progress. Form text and scroll position are set as test fixtures. Flash timers run at their real duration. The content provider supplies only synthetic PGN and backup files. An ActivityMonitor substitutes the selected document result; browsing the system picker UI is not automated.

Phases: `modes`, `learning`, `imports`, `controls`, `assessment`, `seed`, `persistence`. Launch with `adb -s <isolated-emulator> shell am instrument -w -e phase <phase> app.chessvision.trainer.qa/.RuntimeProbe`. Each phase writes `qa-<phase>.json` into the target's external files directory. Run seed before persistence and force-stop the target between them. Do not clear app data. Check the JSON `passed` field; adb can exit zero even when an instrumentation assertion fails. The additional `migration-seed` phase creates a small old-version history and allows WebView time to flush it before an in-place upgrade test.

In the maintained project this runner lives at `tests/android-runtime-qa`. Configure its SDK with `ANDROID_HOME` (or a local.properties sdk.dir), use JDK 17 and the project's Gradle wrapper with `-p tests/android-runtime-qa assembleDebug`, then install its test APK with `adb install -r -t`. `Run-Remaining.ps1` runs the complete six-phase matrix and checks each JSON result; its adb path and emulator serial are intentionally explicit and must be adjusted before using another machine or emulator. The target app must already be installed. Use an isolated emulator: these tests create and restore synthetic training history.

The initial file-import fixture had a missing intent category, then an unsuitable pipe and a file modified during reads. These were corrected in this runner. The final learning phase includes both successful file import and offline network-error checks. A separate actual app defect was then reproduced: 1.1.0 could lose its latest localStorage writes under immediate process termination. Version 1.1.1 adds a key-restricted synchronous native preference bridge, migrates existing v1 history, and keeps a browser storage fallback. The final acceptance reports apply to that repaired APK.

Tests were run only on emulator-5580, a headless read-only session of Medium_Phone_API_37.0, with airplane mode enabled and Wi-Fi/mobile data disabled. No phone or other AVD was changed. Android 17 / SDK 37 is the emulator runtime; the application still targets SDK 34. A single emulator version does not establish compatibility on every supported Android version or physical phone.

Version 1.1.2 adds a clarity phase for instructions, trace reset, set submission and Ready-gated flash. answerRound starts a ready exposure before waiting for masking. To test the UI change, run phase clarity followed by modes, assessment, seed and persistence.
Version 1.2.0 uses phase visual instead of legacy clarity. The runner handles explicit Check, separate first-use demonstrations, editable drafts, visual understanding, focused-session exit and the summary Back to Today control. The visual phase captures both themes and 200 percent text zoom and checks goal/board/action fit. The same production APK is tested with real native touches; answer coordinates are test oracles, not guidance shown to learners.

The readability phase checks the installed white reading surfaces, measured text contrast, full board/action visibility, large-text internal scrolling and header containment, plus neutral future progress segments. It also captures Home, Learn, Games, Progress and lesson screenshots. Version 1.2.3 corrects the all-green progress styling and 200 percent text header overflow reproduced on the emulator. Native rule/scoring and force-stop persistence acceptance continue through the existing modes/learning/assessment/seed/persistence phases.


1.3.0 phases: calibration-seed (answer three), force-stop, calibration-resume (remaining nine), then intermediate-smoke (all eight real-game modes). Install the runner with -t. Check monotonic attempt counts across phases; seed then force-stop/persistence checks exact saved state. Keep the isolated emulator offline. Full mode sessions and final-APK smoke are separate checks.

Course phases: course-seed, force-stop, course-resume, force-stop, course-persistence. Start with no synthetic course history. These use real piece/destination/Check taps, Android Back, whole-line scoring and completed-result recovery. Compare normalized course fields rather than JSON key order. Run seed/persistence afterward to exercise backup/restore including course metadata.
